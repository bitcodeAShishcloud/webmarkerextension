<task type="auto">
  <name>Task 2: Guard null usage in stream and make ScriptedModel null-capable</name>
  <files>src/llm/stream.ts, src/llm/scripted.ts</files>
  <action>
Per D-02, prevent `toUsage(undefined)` from crashing when a server omits usage, and let the fake model reproduce that case.

In `src/llm/stream.ts`, inside `streamTurnNow`, replace:
```
case 'finish-step':
  usage = toUsage(part.usage);
  break;
case 'finish':
  finish = part.finishReason;
  usage = usage ?? toUsage(part.totalUsage);
  break;
```
with:
```
case 'finish-step':
  if (part.usage) usage = toUsage(part.usage);
  break;
case 'finish':
  finish = part.finishReason;
  if (!usage && part.totalUsage) usage = toUsage(part.totalUsage);
  break;
```
`toUsage` already returns null for missing tokens, and `usage` stays null when nothing was reported, so the loop's `if (reply.usage)` fallback to char estimation still applies.

In `src/llm/scripted.ts`, extend `ScriptedReply.usage` to `{ input; output; reasoning? } | null` (default behaviour unchanged when omitted). When `reply.usage === null`, omit the `usage` field from the enqueued `finish` part entirely (do not synthesise defaults), so `streamTurn` sees `part.usage === undefined` and leaves `usage` null. When `reply.usage` is omitted (undefined), keep the existing default of 100 input / 10 output. When provided as an object, use its values as before.
  </action>
  <verify>
    <automated>grep -n "if (part.usage)" src/llm/stream.ts && grep -n "if (!usage && part.totalUsage)" src/llm/stream.ts</automated>
  </verify>
  <done>streamTurn no longer calls toUsage on undefined; ScriptedModel can emit a null-usage reply; existing scripted defaults preserved.</done>
</task>
